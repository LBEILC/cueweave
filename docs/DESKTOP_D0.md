# D0 实施与验收

本文记录桌面宿主的 D0 实施边界和可重复验收入口。阶段完成条件由[路线图 D0](ROADMAP.md#d0宿主与兼容性验证)维护，功能和进程约束由[桌面开发规格](DESKTOP.md)维护。具体运行方法见[桌面工作区 README](../apps/desktop/README.md)，一次性环境与产物结果见[D0 验收记录](desktop/2026-09-04-d0-acceptance.md)。

ASR 的本地或云端选型与实验独立安排，不阻塞 D0；候选方案和接入前提见 [ASR 与模型管理](DESKTOP.md#asr-与模型管理)。D0 不下载 ASR 引擎或模型，也不调用识别服务。

## D0.1：宿主与桥接

入口由[桌面工作区](../apps/desktop/README.md)提供。主进程只加载受控应用资源或本地开发服务器；preload 只暴露固定动作。基础页面提供关于信息与随附许可入口，不放置无效的导入、播放或识别按钮。

- 主进程、preload、renderer 分开构建，输出位于桌面 dist/；Node 与 Web 分开类型检查。
- 隔离 preload 输出单个 CommonJS 文件，打入所需纯依赖，仅保留沙箱允许的 Electron API 引用。[Electron preload 限制](https://www.electronjs.org/docs/latest/tutorial/esm#sandboxed-preload-scripts-cant-use-esm-imports)。
- IPC 校验调用窗口、主 frame、页面地址和运行时参数；错误返回稳定 DTO。Renderer 不获得通用 IPC、文件路径、进程执行或已保存密钥。
- 根验证入口覆盖桌面类型和生产构建；固定 IPC 与资源校验进入纯逻辑测试。真实 Electron 冒烟检查覆盖开发服务器与生产资源两条加载路径。
- 复用 [DESIGN.md](../DESIGN.md) 的视觉规则；官方字体副本保持原始内容并随附许可。应用之间不导入源码。

## D0.2：后台与数据库

后台服务入口、SQLite 原生依赖、electron-builder 配置和目录打包命令已经接入。数据库使用独立实验目录；正式项目 schema 留给 D1。

better-sqlite3 针对目标 Electron ABI 与 x64 架构准备，在 utilityProcess 内实测加载、事务提交、关闭和重开。明确配置原生文件解包，不能用普通 Node 测试代替 Electron 验证。[ASAR 分发限制](https://electron-vite.org/guide/distribution#limitations-of-asar-archives)。

服务的就绪、异常退出、重新连接和应用退出分别验收，旧执行代次的事件不能影响新连接。Windows CI 从根锁文件安装依赖并重跑桌面构建与验收，现有 Linux 验证继续覆盖共享源码与构建。

后台开始引用 @cueweave/core 时，将其 TypeScript 和子路径入口纳入编译。移动目录产物后仍应能运行，不依赖仓库或 workspace 链接。[electron-vite 依赖处理](https://electron-vite.org/guide/dependency-handling)。

## D0.3：本地播放器

文件授权与媒体流协议遵循[媒体导入与播放](DESKTOP.md#媒体导入与播放)。范围解析、资源登记与权限校验由纯逻辑测试覆盖，真实 renderer 验证 Chromium 的加载和 seek 行为。

| 实验     | 输入与动作                                                     | 观察和记录                                                                       |
| -------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 请求范围 | 无 Range、首字节、中段、开放尾部、后缀范围、越界；HEAD、空文件 | 状态码、长度、Content-Range、实际字节；HEAD 无响应体；非法及多范围请求有明确策略 |
| 访问边界 | 未登记或失效 ID、路径穿越、目录、媒体替换、链接目标变化        | 无越界读取；授权撤销后不可新建读取                                               |
| 流释放   | 反复 seek、加载中换片、取消读取、关闭窗口                      | 旧流与句柄释放；内存不随文件大小增长                                             |
| 基础格式 | MP4 H.264/AAC、WebM VP9/Opus；中文、空格和 URL 特殊字符路径    | 解码、时长、声音、首帧与随机 seek 结果                                           |

## D0.4：媒体工具

Windows x64 FFmpeg 与 ffprobe 作为受控资源打包，清单登记来源、版本、SHA-256 和许可证。目录产物执行探测与有限范围的音频提取；工具始终以绝对路径和参数数组启动。

覆盖缺失工具、损坏输入、执行超时、运行中取消、退出应用和服务意外退出。记录父子进程与退出结果，确认进程树清理。播放期间运行探测或提取，确认播放、seek、音量、倍速和全屏仍可操作。

兼容性矩阵包含 MKV、HEVC、多音轨、变帧率、非零起点与损坏输入，分别记录探测结果与实际加载结果。D0 只把真实 renderer 中通过播放和 seek 的样本记为可直放，不因工具能探测就宣称播放器支持。

## D0.5：验收记录与安装

短媒体可用确定性脚本生成，真实媒体用于解码与听视对照。样本保留来源、许可或用户授权依据及内容哈希。大型媒体保存在已忽略的 .fixtures/desktop/；提交生成方法与必要的小型元数据。

每次兼容性实验生成独立记录，至少包含：

- 构建身份：提交与未提交差异标识、锁文件和产物哈希、运行方式（开发、目录产物、安装包）。
- 环境与输入：Windows、设备、Electron 运行时、工具身份、样本 ID 与哈希、探测结果。
- 操作与结果：复现步骤、预期、实测值、通过／失败／未测、证据位置与已知限制。
- 进程清理：取消、正常退出、后台异常退出的观测证据。

原始日志和大型产物留在本地实验目录；提交脱敏报告与复现步骤，不包含私人媒体路径或转录。缩减开发机 PATH 只能作为补充检查，不能替代独立 Windows 环境。安装与签名分别记录，分发门槛遵循[发布要求](DESKTOP.md#验证与发布要求)。

## D0.6：视频链接导入

工作台先读取链接元信息，基础观看默认在线播放，下载作为离线功能独立保留。所有来源都由工作台内的 DOM 播放器呈现。

- 只接受 HTTP(S)；直链逐次校验 DNS 和重定向目标，拒绝本机、内网、链路本地与文档保留地址，最多跟随 5 次重定向，单文件上限 20 GB。
- 网站入口只接受 YouTube 与哔哩哔哩单视频链接，使用 `--ignore-config` 和 `--no-playlist`，不加载用户配置或插件。默认不使用登录状态；用户可在隔离的官方站点窗口中登录，Electron 持久保存该会话，并读取账号有权访问的媒体信息。
- 在线播放不创建下载文件。主进程代理实际媒体流并转发 Range 与站点请求头；renderer 只接收内部媒体 URL。
- 解析结果列出可直接播放的标准 SDR 清晰度和站点已有的人工、自动字幕。YouTube 展示至 1440p（2K）和 2160p（4K）；哔哩哔哩保留 1080P 高码率、1080P60 和 4K 等平台档位。切换清晰度保留播放位置、暂停状态、倍速、音量和当前字幕。
- 下载进度来自实际字节；取消会终止请求或外部进程树，并保留 `.part` 临时文件。相同直链重试时使用 HTTP Range 续传，服务器不接受 Range 时重新写入。
- yt-dlp 2026.08.19 和 Deno 2.9.6 的 Windows x64 官方产物、SHA-256、来源与许可证记录在[工具清单](../apps/desktop/resources/tools/manifest.json)；打包产物从固定资源目录启动，不依赖系统 PATH。

`npm run test:desktop:links` 使用本地受控 HTTP 服务检查 Range 流式播放、重定向、取消和续传；使用 `jNQXAC9IVRw` 检查 YouTube 清晰度清单、人工字幕和流式播放，使用 `LXb3EKWsInQ` 检查 1440p（2K）选项与 3840×2160 VP9 实际解码，使用 `BV1qNtd6sEai` 检查哔哩哔哩未登录读取、1080p 到 720p 的切换与进度连续性，并使用 19 秒公开样本检查独立下载、媒体探测和本地播放。真实站点验收需要网络；站点行为变化时应重新运行，失败不会影响本地文件导入。

## D0.7：统一播放器

本地文件、下载文件和 HTTP(S) 直链由一个 HTML `video` 元素播放。YouTube 与哔哩哔哩由随包 yt-dlp 和 Deno 解析为可用的直连媒体流；同一档位依次优先 H.264、VP9、AV1 和 HEVC，并配对兼容的音频流。H.264 通常覆盖至 1080p，YouTube 2K/4K 使用已实测通过的 VP9。主进程分别代理两路字节，renderer 使用 `video` 与隐藏的 `audio` 元素同步播放。播放器画面参与正常 DOM 布局，可随页面滚动、缩放和进入全屏。

播放器不加载网站 iframe，也不把实际媒体地址、Cookie 或磁盘路径暴露给 renderer。登录窗口没有桌面 preload 或 Node 权限，并使用与主窗口分离的持久会话；后台任务只使用当前站点的一次性 Cookie 文件。在线字幕由后台按所选语言取得并转换为 WebVTT；外部 SRT 与 WebVTT 字幕仍可通过系统文件选择器读取。登录状态仅用于访问用户账号本身有权观看的内容，不绕过付费、DRM 或平台授权；直播和合集仍未实现。

普通清晰度列表当前上限为 2160p，并排除 HDR10 和杜比视界轨道，避免把色彩管理和 10-bit 硬件解码问题伪装成普通分辨率切换。8K、HDR 和杜比视界需要独立的能力检测、色彩与性能验收后再开放。
