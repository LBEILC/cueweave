# CueWeave 开发路线图

路线图只定义交付顺序与阶段完成条件；浏览器扩展要求以[产品需求](PRODUCT_SPEC.md)为准，桌面端要求以[桌面端开发规格](DESKTOP.md)为准。

## 共享翻译核心

算法和提示词优化属于 `packages/core` 的共同演进，不挂在某一个应用阶段下。迁移细节与验收条件见[共享翻译核心](TRANSLATION-CORE.md#迁移顺序与完成条件)。

| 阶段 | 交付目标                                     | 当前状态                                   |
| ---- | -------------------------------------------- | ------------------------------------------ |
| C0   | 明确职责、两种时间处理方式及现状             | 文档已明确                                 |
| C1   | 桌面固定 cue 翻译的通用逻辑收敛到核心        | 待实施                                     |
| C2   | 两条路径共享任务、档位、版本、取消与结果契约 | 待实施；词元三档已接入扩展                 |
| C3   | 统一评分、未见样本和版本对照基线             | 已有工具基础；正式三档评分与代理盲评待进行 |
| C4   | 两端接入等价性及各自生命周期验收             | 待实施                                     |

应用开发可继续推进；新平台通用翻译逻辑需标明迁移归属，不以引用共享传输代替完成 C1/C2。C3 可在契约迁移前评审已有输出，评测必须绑定其实际入口和版本。

## 桌面应用

Electron 桌面端在 `apps/desktop` 开发，通过 `@cueweave/core` 复用字幕能力。D0–D3 构成首个可用桌面版本；原 D4 的首批视频链接导入已前移到 D0.6，D0.7 将所有媒体来源统一到 DOM 播放器，D5 扩展批量处理。阶段以验收结果推进，不按预估日期跳过依赖。

### D0：宿主与兼容性验证

状态：实现完成并通过本机目录产物与安装包验收；Windows CI 在日常推送中复验构建与功能，安装包改为手动触发复验。发行签名仍是公开分发前置条件。

- 建立主进程、隔离 preload、React 页面、固定 IPC 和桌面构建命令；用真实文件完成打开、播放与 seek。
- 验证媒体协议的 Range 请求、常见媒体样本、中文路径、后台工具运行、SQLite 原生模块及安装包资源定位。
- 验证后台媒体工具的取消和退出清理。ASR 选型与实验独立安排，不作为 D0 的前置条件。
- 接入 HTTP(S) 媒体直链、YouTube 和哔哩哔哩单视频；先展示元信息，基础观看由 DOM 播放器流式播放，离线下载复用同一播放器。支持标准 SDR 至 4K、平台高码率与高帧率档位、站点已有字幕、软件内隔离并持久保存的站点登录状态、实际下载进度、取消与直链续传。

完成条件：打包产物在无开发工具链的 Windows x64 环境完成播放、数据库读写与媒体工具调用，并产出媒体兼容性与进程清理记录。不得以空窗口作为阶段完成。

D0 的实现边界、复验入口和结果链接见 [D0 实施与验收](DESKTOP_D0.md#分批交付)。

### D1：字幕导入、项目与导出闭环

状态：本机核心闭环已实现并通过静音功能验收，范围与复验入口见 [D1 实施与验收](DESKTOP_D1.md)。

- 实现项目数据库、原始媒体引用、SRT / WebVTT 导入、字幕同步、字段编辑、时间调整与撤销重做。
- 接入自动保存、关闭恢复、媒体重新定位及原文字幕导出；建立持久任务与 IPC 修订契约。

完成条件：用户打开视频并导入字幕，完成编辑，重启后继续工作，导出结果可回读且与保存修订一致；恢复与磁盘不足不会损坏项目。

### D2：翻译与完整性

状态：已实现保留 cue 时间的翻译、持久检查点、取消续做、人工译文校对和译文／双语导出；设置页增加字幕显示与预览。范围与验证入口见 [D2 实施与验收](DESKTOP_D2.md)。真实模型语言质量和可信词级输入仍需分别验证。

- 实现保留 cue 时间的翻译入口，接入共享传输与校验、Provider 设置和密钥保存。
- 实现窗口检查点、进度、取消、失败重试、人工修订保护，以及中文和双语导出门槛。
- 仅对单独通过词对齐验收的输入接入词级重组，不将估算时间作为事实；已有字幕的翻译不依赖 ASR 选型。

完成条件：整片已有字幕可翻译、校对、保存与导出；超时、取消、崩溃恢复和旧结果返回不覆盖人工修改，未完成结果不能被标为完整导出。

### D3：ASR 接入与首版验收

- 先确定本地或云端 ASR 路线，再安排短音频、段级时间及可选词对齐实验。
- 实现音轨选择、音频提取、识别适配、时间映射和识别恢复；本地路线增加模型管理，云端路线增加上传确认、凭据保护、费用提示与请求取消。
- 打通无字幕视频到识别、翻译、校对、保存、导出的完整流程，验证一小时级媒体和后台播放响应。
- 完成资源许可证清单、安装包、故障反馈与项目迁移验收。

完成条件：无字幕的本地视频可完成全部流程；静音、重复台词、音轨变化、模型损坏与中断恢复有确定结果；安装包不依赖用户预装 Node、Python 或 FFmpeg。

### D4：已并入 D0.6

HTTP(S) 媒体直链、YouTube 与哔哩哔哩公开单视频的流式播放已经前移并完成，YouTube 与直链离线获取可用。字幕来源选择及从链接到字幕导出的闭环随 D1–D3 的字幕、翻译与 ASR 能力逐步补齐，不另设重复的链接导入阶段。

### D5：批量处理

- 在单视频任务契约上增加多项目队列、资源限额、批量输出目录和失败项重试。

完成条件：一项失败不阻塞其他项目；项目之间的媒体、密钥引用、字幕和输出目标不会串用；暂停与退出后可恢复队列。

以下 Phase 0–7 描述浏览器扩展的交付。

## 当前进度

- Phase 0、1、1.5、2、3 已完成核心实现并有自动化测试；长语法句中的并列和从句可触发定向 AI 显示边界复审，并由真实视频时间点样本覆盖。
- Phase 4 已完成当前位置优先、前方窗口预取、并发限制、任务去重、进行中请求主动取消、YouTube 单页导航会话隔离、IndexedDB 持久缓存、稳定缓存键、LRU，以及当前视频/全部缓存管理；仍需 Service Worker 恢复专项验收。
- Phase 5 已完成 Popup、独立 Options、字幕工作台、原文/中文/双语模式、双语顺序、字号、位置、字幕文字底板、高置信度转录修正、自动与人工视频术语、术语变更后当前位置重译和完整视频翻译进度；仍需颜色/字重以及影院、全屏、Shorts 的完整验收。
- Phase 6 已完成 SRT / WebVTT 序列化、导出校验和原始转录/修复原文/中文/双语导出入口；仍需常见播放器兼容性回读验收。
- Phase 7 尚未开始。

## Phase 0：项目基础

- 建立 WXT + TypeScript Manifest V3 工程。
- 配置开发、构建、类型检查、测试和打包命令。
- 补做上游固定提交的本地审计。
- 建立第三方版权声明。
- 生成可被 Chromium “加载已解压的扩展程序”接受的最小产物。

完成条件：干净安装可以生成扩展产物；浏览器能加载；静态检查与空测试套件通过。

## Phase 1：字幕管线

- 建立领域数据结构和版本化消息协议。
- 实现字幕获取适配层。
- 实现标准化、噪声识别和滚动去重。
- 实现本地规则断句。
- 加入固定字幕样本与边界测试。

完成条件：不接入模型也能从样本稳定生成带时间轴的本地显示字幕；真实页面能显示降级原文字幕。

## Phase 1.5：词级时间与显示分层

- 保留 YouTube JSON3 的词级时间偏移。
- 将完整语义句与屏幕显示字幕拆成独立领域结构。
- 本地降级识别 cue 内部标点，并在从句或短语附近限制显示长度。
- 建立连续词元窗口、覆盖校验和中文显示长度约束。

完成条件：真实长句不会在冠词、助词或未完成短语后被硬截断；模型输出可以映射回程序持有的词级时间；不合规输出可靠回退原文。

## Phase 2：OpenAI 兼容 Provider

- 建立 Provider 契约和统一错误分类。
- 支持 Chat Completions、Responses 与自动检测。
- 实现运行时 origin 权限。
- 建立 Provider 设置页和连接测试。
- 使用本地模拟服务覆盖成功与故障路径。

完成条件：无需真实 API Key 即可跑完 Provider 集成测试；密钥不会离开 background 上下文。

## Phase 3：AI 语义重组

- 构建上下文窗口与提示词版本。
- 实现 JSON Schema 和 cue 完整性校验。
- 实现一次严格重试与本地降级。
- 将合法分段映射回程序时间轴。

完成条件：遗漏、重复、乱序、未知 ID 和非法 JSON 均被测试捕获；所有失败都产生可显示的降级字幕。

## Phase 4：调度与缓存

- 实现播放位置优先队列、并发限制和取消。
- seek 后重新排优先级。
- 实现 IndexedDB 缓存、缓存键和 LRU。
- 处理 Service Worker 回收与视频切换。

完成条件：seek 与快速换片不会串结果；相同有效输入命中缓存；配置变化可靠失效。

## Phase 5：产品界面

- 完成 Popup 和 Options 信息架构。
- 完成原文、中文和双语模式。
- 完成字幕样式与播放器内状态。
- 适配影院、全屏和 Shorts。

完成条件：常用操作无需进入设置页；所有错误给出发生位置和恢复动作；键盘与缩放可用。

## Phase 6：字幕导出

- 实现 SRT 与 WebVTT 序列化。
- 实现时间、编号、内容和文件名校验。
- 加入中文、双语和修复原文导出入口。

完成条件：固定样本通过解析回读测试，并可被常见播放器读取。

## Phase 7：发布准备

- 完成端到端与手工验收矩阵。
- 审核权限、CSP、隐私说明和第三方许可证。
- 生成可安装 ZIP 和可复现构建记录。
- 整理已知限制与发布说明。

完成条件：CI 从干净检出生成通过验收的安装包，仓库中不含密钥、字幕缓存或用户数据。
