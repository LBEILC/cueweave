# 翻译核心评分标准 v1

版本：`translation-quality-v1`。状态：可执行的内部评测标准，**尚未经过独立人工校准，不是翻译准确率或发布认证**。评分逻辑与等级锚点的唯一代码来源为 [`translation-scoring.ts`](../scripts/eval/translation-scoring.ts)；标准内容哈希随评审保存。修改权重、锚点、严重程度或汇总规则时必须升级版本，不用新公式重算旧评审后冒充原分数。

本规范属于[共享翻译核心](TRANSLATION-CORE.md)，同样约束速度、均衡、质量档。评价对象是最终交付字幕；产品里的模型复核不是评分裁判。当前工具接入的是已有英文到简体中文的词元基准结果，固定 cue、多目标语言和实际音画同步尚需各自适配与校准，不能直接外推。

## 评分范围与证据

- 原始输入是最终依据，参考译文只提供可接受的意思和边界说明，不要求字面相似。保留缺少证据的 ASR 原拼写不算错误。
- 只对 `scoreTokenIds` 对应的信息评分。边缘字幕可以跨入上下文，应连同原文审阅；不能因没有翻译计分范围外的信息而扣分。
- 先逐项填写 `meaningVerdicts`，再完成四维等级。原有语义要点统计保留为核查清单，不再额外乘入总分，以免同一遗漏重复扣分。`context-only` 只用于参考中边界外的补全，并在 notes 说明；不能把难题随意排除。工具拒绝全部排除和明显评分矛盾，但无法自动判断人工排除是否合理，仍需复核。
- 每个问题有唯一 ID、受影响维度、严重程度、原文词元 ID、最终字幕索引、原文/译文引文和解释。工具核对引文和索引是否存在及是否关联计分原文；它验证证据位置，不声称自动证明语义判断正确。
- 同一个问题只建一个 ID，可关联多个确实受影响的维度。不要因涉及两条字幕便记录两次。多个重复发生的独立错误可分别记录，汇总保留错误数量和受影响片段数量。
- 没有评审时等级为 `null`，不是 0，也不是满分。完成评审必须填写评审者、来源（human / agent / mixed）、`reviewStatus: complete`、版本和对应快照哈希。

## 四维等级和权重

每个维度使用 **0–4 整数等级**，不允许随意填 83 或 87 一类直接总分。4 表示逐项检查未发现该维度的问题，不要求只有一种正确措辞。3 为轻微问题，2 为实质问题或多处局部问题，1 为严重问题，0 为该维度基本失效。具体锚点如下：

| 维度                   | 权重 | 4                                | 3                          | 2                                    | 1                                    | 0                          |
| ---------------------- | ---: | -------------------------------- | -------------------------- | ------------------------------------ | ------------------------------------ | -------------------------- |
| 语义准确 accuracy      |   40 | 实义正确，允许等价表达           | 局部轻微偏差，不改核心命题 | 至少一处实质错误或多处偏差           | 核心否定、条件、数字或对象等翻错     | 核心意思普遍错误或不可理解 |
| 信息完整 completeness  |   25 | 实际信息完整，无无依据增译或重复 | 次要信息漏、增或重复       | 重要信息漏、增、重复，或多项次要问题 | 大部分计分信息未正确交付             | 基本未表达计分内容         |
| 对应与可读性 alignment |   20 | 每条原文译文对应，切分可读       | 轻微衔接或节奏问题         | 实质跨条错位或明显妨碍跟读           | 多处明显错位、说话人错配或不可读切分 | 归属/顺序普遍混乱          |
| 自然度与一致性 fluency |   15 | 自然清楚，术语一致               | 少量生硬或轻微不一致       | 多处明显生硬或不一致                 | 大量不通顺，需反复猜测               | 中文基本不可理解           |

计算方式：`总分 = Σ(维度等级 ÷ 4 × 权重)`。保留原始等级与未提前舍入的分项，报告展示两位小数不代表有小数级的评审精度。历史 1–5 流畅度只用于旧报告；新报告为了兼容旧表格显示 `level + 1`，实际加权始终使用 0–4。

扣分等级必须关联问题证据；4 分也必须写核对理由。仅因为句子长或中文字符多，不直接判语义错误；现有展示风险阈值是提示，评审者须判断是否真的妨碍阅读。时间来自插值时，不得据此声称完成听音同步评分。

## 严重错误与完整性门槛

| 等级     | 判定                                                     | 对受影响维度的约束 |
| -------- | -------------------------------------------------------- | ------------------ |
| minor    | 次要细节或表达问题，不改变核心命题                       | 最高 3             |
| major    | 实质信息改变/遗漏，或明显破坏归属与阅读                  | 最高 2             |
| critical | 核心否定、条件、关键数字或主体错误，使结论或行动理解反转 | 最高 1             |

严重程度取决于具体上下文，不是“出现一个数字错误就一律 critical”。例如普通名称拼写差异和把命令的否定翻反不应同罚。等级与严重程度矛盾时工具拒绝出报告。

- 有 major 或 critical，片段始终标为 `needs-fix`，即使加权分很高。总分不再额外重复扣固定罚分；门槛和错误计数独立显示。
- 缺少计分范围的实际输出，标为 `incomplete`，不给总分；已产出部分仍可记录分项、证据与覆盖率。完全未产出时完整性为 0，另外三维为 null，不评价不存在的译文。
- 缺失只发生在边界上下文时，不据此扣计分范围的质量分；运行本身的 partial 状态仍单独保留。
- 无严重错误且完整时，暂以 ≥90 为 `strong`，80–<90 为 `usable`，70–<80 为 `needs-improvement`，<70 为 `needs-fix`。这些是待校准的内部报告标签，不承诺达到人工译者水平或自动批准发布。

示例：关键否定翻反，准确性为 1，其余三维为 4，加权得到 70，但结论仍为“需修复”。不能把它描述成“七成准确”。

## 汇总与比较

先对同一视频的计分片段等权平均，再对视频等权平均。主集、development、holdout 和诊断集分别提供视图；主集汇总明确包含 development 与 holdout，诊断集不混入主集。任何纳入的片段不完整，则对应视频及组的总分为 null，不能静默丢掉失败样本只平均成功结果。

严重问题保留原始数量、需修复片段数和不完整片段数。总分高不等于所有片段可用。首次可用时间、整段时间、请求数、报告用量和缺失用量独立记录，不加入质量分。无首次可用记录不填 0；对照工具同时显示有效记录数。

同一标准、参考哈希、输入哈希和选集才能比较总分。模型、模式或实现版本可以变化，但需保留每次实际运行的身份与快照；评审者变化也是混杂因素。每轮报告独立列出，不只选最佳输出，不自动混合多位评审者分数。模型/策略迭代可复用此标准，比较前应冻结候选，再评新视频与重复运行。

## 使用步骤

以下命令在仓库根目录运行，完全离线，不调用翻译或裁判模型。新输出目录必须不存在。

```powershell
# 1. 从已保存输出和冻结参考生成匿名材料与待填模板
node --import tsx scripts/prepare-translation-review.ts --run .eval/benchmarks/three-modes-speed-final --out .eval/reviews/candidate-a

# 2. 复制 judgments.template.json 为 judgments.json，按材料逐项填写
# 完成后设 reviewStatus=complete，并填写 reviewer 与 reviewerType

# 3. 校验证据并生成百分制、分项、严重错误与宏平均报告
node --import tsx scripts/report-translation-benchmark.ts --run .eval/benchmarks/three-modes-speed-final --judgments .eval/reviews/candidate-a/judgments.json --out .eval/reviews/candidate-a/assessment

# 4. 其他候选也完成评分后，生成同范围对照
node --import tsx scripts/compare-translation-scores.ts --out .eval/reviews/comparison .eval/reviews/candidate-a/assessment .eval/reviews/candidate-b/assessment
```

`--references` 可以指定另一份冻结参考；准备和报告工具均校验参考锁、输入及结果哈希，拒绝把旧评审套到续跑新输出。

准备产物：

- `packet.json`：原文词元、计分范围、参考说明、匿名候选字幕和完整评分标准，不包含档位、模型、耗时或恢复过程。
- `judgments.template.json`：所有等级和语义判定为空的 draft。模板不可直接生成正式得分；`issues: []` 顶层兼容旧报告，新的评分证据填写在 `scoreCard.issues`。
- `coordinator.json`：真实候选身份与运行目录，只供组织者使用，不给盲评者。

评分片段的 `scoreCard` 格式示意（省略其他三维，不是完整可提交文件）：

```json
{
  "ratings": {
    "accuracy": {
      "level": 1,
      "rationale": "核心否定翻反",
      "issueIds": ["e1"]
    }
  },
  "issues": [
    {
      "id": "e1",
      "dimensions": ["accuracy"],
      "severity": "critical",
      "sourceTokenIds": ["t0", "t1", "t2"],
      "cueIndices": [0],
      "sourceQuote": "Do not go",
      "translationQuote": "去",
      "explanation": "原文禁止行动，译文变成行动指令"
    }
  ]
}
```

字幕索引从 0 开始，必须引用最终输出数组；原文引文要能在所列词元按顺序连接的文字中找到。未产出来源可用空字幕索引与空译文引文，必须确实属于缺失来源。扣分应说明受影响的实际意思，不只写“不自然”或“感觉不好”。

## 代理盲评与校准

本次实现只准备工具，不自动派发代理或给真实候选打分。后续盲评应使用不继承算法优化对话的独立评审上下文，只提供匿名材料和标准；随机候选顺序、隐藏档位映射。组织者不得提前给分数区间或泄露哪个候选预计更好。

先用少量相同样本让至少两位评审独立打分，保留原始评审，比较四维等级、严重程度与候选偏好分歧。关键错误判定不同或等级差超过一级时，逐条核对证据后单独记录裁决，不能覆盖原评审，也不简单投票当作真相。代理可能共享偏差，至少保留一部分样本由用户实际观看校准。当前工具未实现评审者一致性统计或自动裁决；这部分仍是后续能力。

旧格式评审照常输出要点与流畅度，但 `quality: null`、`legacy-unscored`，不自动转换成新标准总分。之前对三档的主观估分不作为标签、参考答案或校准目标。
