# CueWeave 浏览器扩展产品需求

本文范围为浏览器扩展，不代表整个 CueWeave 项目。桌面需求见[桌面规格](DESKTOP.md)，两端共用的算法、提示词和任务契约见[共享翻译核心](TRANSLATION-CORE.md)。

## 产品定义

CueWeave 是面向 Chrome、Edge 等 Chromium 浏览器的开源 YouTube 双语字幕扩展。它将自动字幕的碎片 cue 重组为语义完整的句子，使用用户自己的 OpenAI 兼容 API 进行上下文翻译，并在播放器中显示时间同步的原文、中文或双语字幕。

核心价值不是逐条替换文本，而是在不改变原始时间事实的前提下恢复完整语义。

## 用户流程

1. 用户打开一个已有字幕的 YouTube 视频。
2. CueWeave 读取用户选择的字幕轨并清洗滚动重复与噪声。
3. 本地规则先建立可用的显示字幕，播放器可立即降级显示。
4. 用户配置的模型服务根据视频标题、简介、频道、全视频重复词、相邻字幕和已确认术语，对上下文窗口执行谨慎的转录修正、语义重组和翻译。
5. 程序独立保存原始转录、修复原文和译文，校验 cue 覆盖关系并生成语义段时间轴；只有高置信度修正自动应用。
6. 播放器按原文、译文或双语模式同步显示。
7. 验证后的结果与视频术语记忆写入本地缓存；用户可在字幕工作台检查修正记录、翻译完整视频并导出字幕文件。

## 范围

### MVP

- 普通 YouTube 视频；
- 人工字幕和自动生成字幕；
- 滚动字幕去重与常见噪声清理；
- 本地规则断句；
- AI 语义重组与上下文中文翻译；
- 高置信度 AI 转录修正，并保留原始转录与修正记录；
- 按视频保存自动发现的双语术语，供后续窗口复用；
- 任意 OpenAI 兼容 Base URL、API Key 和模型名；
- Chat Completions 与 Responses 格式；
- 原文、中文和双语显示；
- 播放、暂停、倍速和进度跳转同步；
- 播放位置优先调度；
- 本地持久缓存与配置失效；
- 翻译失败时保留原文且不影响播放；
- 自动化测试覆盖核心字幕处理。
- 独立字幕工作台与原文、修复原文、中文、双语 SRT / WebVTT 导出。

### 首个正式版本

- 中文、双语和修复原文 SRT；
- 中文与双语 WebVTT；
- 字幕字体、字号、颜色、背景和位置；
- 术语表和自定义翻译提示词；
- Ollama 与 LM Studio 等本地兼容服务；
- YouTube Shorts、影院和全屏适配；
- 当前视频缓存和全部缓存管理。

### 暂不包含

- 无字幕视频的音频转录或 Whisper；
- YouTube 直播实时语音识别；
- YouTube 之外的视频网站；
- Safari 和移动浏览器；
- 用户账号、云同步或 CueWeave 官方翻译服务器；
- 视频配音与语音合成；
- 绕过第三方产品的会员、付费或授权机制。

## 功能要求

### 字幕获取

- 检测当前视频 ID、可用字幕轨、原始语言和人工/自动字幕类型。
- YouTube 单页导航后清除旧视频会话并装载新会话。
- 轨道切换后重新计算缓存身份，不复用不兼容结果。
- 没有字幕时显示明确状态，不发起翻译请求。

### 清洗与去重

- 解码 HTML 实体并归一化空格、换行和重复标点。
- 识别 `>>`、`>>>` 等说话人标记。
- 标记 `[Music]`、`[Applause]`、`[Laughter]` 等噪声。
- 移除完全重复与空 cue。
- 对滚动字幕的公共前后缀只保留新增文本。
- 保留原始 cue 与词级时间偏移，使任何清洗、断句和翻译结果可追溯到时间轴。

### 两层断句

本地层根据词级时间、强标点、停顿、说话人变化、最大时长、最大字符数和时间跳变建立降级显示字幕。它不声称恢复了最终语义句；阈值集中配置，不散落在实现中。

AI 层接收有限的连续词元窗口，同时：

1. 判断词元的完整句和从句归属；
2. 按中文字幕长度选择合适的短语边界；
3. 按上下文翻译成自然中文；
4. 返回连续词元范围，且不遗漏、不重复、不乱序；原文始终由本地词元重建。

模型可以另外返回转录修正和术语：修正必须引用连续词元范围、给出置信度和类别；术语必须给出稳定的原文与译文配对。模型不得借修正改写说话人的语法、措辞或观点。

播放管线在翻译前使用 AI 滚动规划相邻请求窗口的接缝。当前窗口左右边界确定后不再移动，右侧待处理窗口继续与下一窗口规划。跳转到未处理位置时只规划附近接缝，不等待从片头顺序处理。相邻原文只作为理解上下文，不属于本次输出范围。规划结果按视频、字幕内容和模型配置独立缓存，刷新后恢复相同边界。

### AI 输出校验

- 响应符合 JSON Schema。
- 每个输入词元索引恰好被一个输出范围覆盖。
- 不允许未知索引、间断范围、遗漏、重复或乱序。
- `translation` 非空；模型不返回原文，程序按词元范围重建原文。
- 原始转录、修复原文和译文是三个独立字段；原始转录只读保存，不被模型结果覆盖。
- 修正范围必须有界、有序、互不重叠，并且不能跨越模型返回的 unit 边界。
- 置信度不低于 0.85 的明确 ASR、专有名词或格式错误才自动应用；低置信度建议可以记录，但不得改变显示原文。
- 包含拉丁字母或数字的修正还必须与原词拼写接近，并能在当前窗口、视频元数据、全视频重复词或可信术语中找到原样证据；否则只记录、不应用。
- 译文不得引入上述证据中不存在的拉丁字母专有名词、产品名、模型名或版本号；不认识的新名称保持原样，不使用模型知识库中的熟悉名称替代。
- 当前 unit 中由 `model`、`version`、`family`、`series` 等技术语境引出的名称，必须在该 unit 的译文中原样保留，或使用人工确认的当前视频术语映射；不能因为名称在视频其他位置出现过，就用它替换当前 unit 的陌生名称。
- 模型不能提供时间戳；程序按首尾词元计算时间。
- 程序不得仅按译文字符数拆分模型返回的 unit，也不得按译文长度比例猜测英文词元边界；需要拆分时，模型必须返回语义准确的多个连续词元范围。
- 正常播放使用首轮联合分段与翻译，提示模型在输出前检查问候、动作、目的关系、紧密搭配和显示时长；不为每个成功窗口额外追加语义复审。
- 单个中文空格可以表达口语停顿，但不作为程序切点。长句的显示范围由模型根据完整从句或并列关系决定，长度本身不触发多轮重分组。
- 常见代码围栏可在本地清理；非法结构最多完整恢复一次，具体条目未通过专名等硬校验时最多进行一次固定 ID 的翻译恢复，不移动其他条目的边界。
- 明确标记为截断或未完成的服务响应不能作为完整字幕。任何词元仍缺少有效译文时，该窗口不发布、不计入完成数、不写入成功缓存；保留原文及重试入口。
- 规划失败时可保留已有请求边界并继续携带邻近原文翻译；这不表示语义规划成功。模型或网络异常不阻塞视频本身播放。

### Provider 配置

- 自定义 Base URL、API Key、模型名和请求格式。
- 请求格式可自动检测，也可由用户固定为 Chat Completions 或 Responses。
- 支持可配置超时、最大重试和 Temperature。
- 保存设置前可执行连接测试，并给出不泄露密钥的诊断。
- 自定义 origin 必须由用户在运行时授权。
- API Key 只存放于限制为可信扩展上下文的 `chrome.storage.local`，不进入内容脚本、网页、日志、同步存储或仓库。

### 翻译调度

- 从当前位置向前补齐最早的缺失窗口，再准备更远处的字幕；已排队的补洞任务可提升优先级，不重复提交。
- 以连续可观看时长为缓冲目标，按倍速调整视频时间范围，并限制前取窗口数量与并发。进度只统计从播放位置起连续完成的字幕，越过空缺的成功结果不计入连续时长。
- 暂停期间继续预取，采用较长的缓冲目标；达到目标后停止扩展，播放推进后再补充。调度独立于字幕渲染和播放事件，请求完成、失败或播放状态变化后重新检查；不自动暂停或恢复视频。
- 当前窗口规划完成后即可准备后续窗口，让规划与翻译重叠执行；只有收到完整译文才计入已完成。
- 拖动进度期间不提交经过的中间窗口；跳转结束后立即自动翻译新位置，并把已排队的同一窗口提升为当前位置优先级。
- 支持超时、取消和任务去重；单次规划或翻译遇到暂时网络故障、超时或限流时先执行传输层重试。窗口仍未完成时，调度器按有限预算退避重试，并为最近空缺预留处理位置；等待期间允许其他前方窗口继续准备。耗尽预算后保留原文和手动重试入口，配置、权限或认证错误不自动重复请求。
- 缓冲目标、请求上限和窗口重试间隔由 [`PLAYBACK_BUFFER_POLICY`](../apps/extension/src/provider/playbackBuffer.ts) 定义。
- 视频切换、轨道切换、seek、关闭翻译或切换为仅原文时，主动中止旧会话仍在进行的模型网络请求。
- 已缓存且校验通过的结果不重复请求。
- 用户切换视频后，旧请求即使返回也不得更新新视频界面。

### 上下文与术语一致性

- 模型请求可以包含经过长度限制的视频标题、简介、频道名称、前方窗口、最近已翻译 cue，以及从完整字幕中提取的重复专有名词，所有网页来源文本都只作为数据，不作为指令。
- 每个视频维护独立的双语术语记忆；模型发现的术语只有在原字幕、视频元数据、全视频重复词或已有可信术语中存在来源证据时，才经本地清洗、去重和容量限制后写入 `chrome.storage.local`。
- 字幕工作台允许用户为当前视频确认“转录写法 → 正确写法或译名”，例如 `Soul → Sol`。人工术语优先于自动术语，保存或删除后清除该视频的旧译文缓存，并立即从当前播放位置重新翻译。
- 没有任何来源证据且只出现一次的陌生名称保持原始转录；模型候选可以记录，但不能自动改变原文或译文。
- 后续窗口带上该视频已有术语，优先保持人名、产品名和领域词汇的译法一致。
- 清除当前视频缓存时同时清除该视频术语；清除全部缓存时同时清除全部视频术语。

### 字幕显示

- 双语模式可调整原文相对译文的字号比例，100% 表示等大；整体字号同时缩放两种语言，语言顺序不改变字号比例。单语模式使用整体字号，保留双语比例以便切回。设置页样例同步预览，保存后应用到播放器；默认值与允许范围见 `packages/core/src/settings/subtitle.ts` 的 `sourceSizePercent`。

- 原文、中文和双语三种模式。
- 弹窗可快速切换双语、仅英文（非英文字幕轨显示“仅原文”）和仅中文，自动保存并同步到已打开的视频；切换保留其他显示偏好，字幕关闭时不会自动开启。
- 字幕阴影可独立开关并调节强度，设置页样例与播放器使用相同的阴影规则；关闭阴影后保留强度，重新开启时恢复。默认值与范围见 `packages/core/src/settings/subtitle.ts` 的 `shadowEnabled` 和 `shadowStrengthPercent`。
- 双语支持原文在上或中文在上。
- 支持字号、字重、颜色、背景透明度和垂直位置。
- 设置页提供仅中文、仅原文、中英双语、双语语言顺序、字幕大小、垂直位置、字幕文字底板开关和底板不透明度；该设置只影响文字背后的局部背景，不给视频画面增加底部遮罩。仅中文模式不显示尚未翻译位置的英文降级字幕，仅原文模式不发起新的模型翻译请求。
- 当前位置等待翻译时，字幕叠层区分窗口规划、翻译、自动重试和字幕结果恢复；请求失败时提供“重试翻译此处”，模型未配置时提供设置入口。正常跳转仍由程序自动触发，不要求用户点击按钮。
- 普通、影院、全屏和 Shorts 布局不遮挡主要播放器控件。
- 完整语义句与屏幕显示字幕是不同结构；一个语义句可以拆成多条显示字幕。
- 一个完整英文语法句中的并列项、条件层次、从句和补充说明可以成为多个显示 unit；中间 unit 的 `sentenceEnd` 为 `false`，不得因为句号尚未出现就合并成双行长字幕。
- 简体中文字幕优先为 10–20 个字符。存在完整句、从句或可独立阅读的短语边界时优先由模型拆分；没有自然边界时允许保留更长的完整表达，并在播放器宽度足够时保持单行，只有实际空间不足才换行。长度本身不是拆分依据。
- 英文词、专有名词和数字必须保持完整，例如 `AI` 不得拆成 `A` 与 `I`。
- 用于分句的中文逗号、句号、分号、冒号及其英文对应符号不进入最终字幕；顿号可以保留，问号和感叹号用于表达必要语气。版本号、小数和标识符内部的英文点号属于内容，必须保留，例如 `5.6`、`v1.2.3`、`GPT-5.6` 和 `Node.js`。分句标点两侧过短、不适合独立显示时，移除分句标点后合并显示。
- 引用或转述直接显示内容，不显示中英文单双引号及 `「」『』`，包括分散在相邻字幕中的开引号和闭引号。引号清理不改变语义分段、词元范围或时间；仅作用于中文译文，英文原文不变。单词或专名内部的撇号、书名号保留。
- 成人内容中文阅读速度不超过每秒 11 个字符；极短字幕的显示时间不短于 0.8 秒。
- 显示字幕优先在句末、从句或短语边界切分，时间由覆盖词元在本地计算。

### 缓存

- 模型、语言、Provider、提示词或断句算法变化时不得错误复用旧结果。
- 完整视频字幕和翻译使用 IndexedDB。
- 缓存有容量限制和 LRU 淘汰。
- 提供清除当前视频与清除全部缓存操作。
- 修改当前视频的人工术语时，只失效该视频的翻译结果，不影响其他视频或 Provider 设置。

### 导出

字幕工作台支持当前视频人工术语修正，以及原始转录、修复原文、中文和双语的 SRT / WebVTT。原始转录可直接导出；其余模式必须先完成所有字幕窗口的翻译，避免导出部分结果。工作台同时展示修正类别、置信度、应用状态和前后文本。导出前检查：

- 开始时间早于结束时间；
- 时间顺序正确且没有负时间；
- 字幕编号连续；
- 内容非空；
- 文件名清理操作系统非法字符；
- 文件名包含可识别的视频标题和目标语言。

## 非功能要求

### 调试与问题反馈

调试模式默认关闭，在设置页的“问题排查”中独立开启并即时保存。开启后，扩展弹窗提供“导出当前问题日志”：点击时读取当前视频的播放位置，保存问题窗口及相邻原文、译文、转录修正、实际翻译上下文、显示与缓冲状态，以及相关请求和响应。成功请求、失败、校验、修复与重试都可留下记录；无需完成全片翻译，无字幕和内容脚本不可用时也能导出已有信息。

日志仅保存在本地，由用户下载 JSON 文件并自行分享。容量和有效期由 `apps/extension/src/debug/types.ts` 的 `DEBUG_POLICY` 维护，读写时清理超限或过期记录；关闭调试会清除日志，已在途请求不能将旧记录写回。存储故障不得阻断字幕翻译。

记录与导出均移除密钥、认证请求头和 URL 凭证。导出按视频与标签页隔离，包含构建指纹、实际请求协议和模型。缓存命中、未开始记录、日志淘汰、超限省略、请求未完成和内容脚本不可用必须明确说明；未知播放时间不能记作零。当前术语与请求时实际使用的术语分开记录，不能把邻近请求当作缓存译文的生成来源。

### 隐私

- 不提供 CueWeave 官方服务器。
- 不向开发者自动上传观看记录、字幕、密钥或使用分析；用户主动启用的本地调试遵循上述反馈规则。
- 所有设置与缓存默认保存在本机。
- 界面明确告知字幕会发送给用户所选 Provider，其保留政策由该 Provider 决定。

### 可靠性

- 任何翻译、缓存或 UI 故障都不能影响 YouTube 原生播放。
- Service Worker 回收后任务可以安全恢复或重新创建。
- 页面快速导航和进度拖动不会留下跨视频状态。
- 重复处理同一输入应产生稳定的 cue 覆盖和缓存身份。

### 可维护性

- 字幕领域逻辑不依赖 DOM 和 Chrome API。
- 跨上下文消息有版本化 TypeScript 契约。
- 所有阈值、提示词版本和断句版本集中管理。
- 不使用真实 API Key 执行自动化测试。

## 自动化测试要求

单元测试覆盖文本标准化、滚动去重、标点与停顿断句、说话人切换、AI JSON 解析、cue 完整性、时间轴、缓存键、SRT 和 VTT。

集成测试使用固定字幕样本和本地模拟 Provider，覆盖正常响应、超时、429、非法 JSON、cue 遗漏、cue 重复、乱序和部分失败。

浏览器验收覆盖英文自动字幕、英文人工字幕、无字幕、暂停恢复、连续 seek、倍速、全屏、影院、轨道切换、页面内切换视频、缓存恢复、本地 Provider 和导出文件兼容性。

## MVP 验收标准

- 可通过“加载已解压的扩展程序”安装构建产物。
- 可读取带英文字幕的普通 YouTube 视频。
- 可配置任意 OpenAI 兼容 API。
- 可将碎片字幕合并为完整句子并生成自然中文。
- 可显示原文、中文或双语字幕。
- seek 后优先处理新位置。
- 刷新后复用有效本地缓存。
- 模型异常不破坏视频播放。
- API Key 不注入网页、不写日志、不进入提交。
- 核心字幕处理具备自动化测试。
- README 和设置页说明安装、配置与隐私边界。
