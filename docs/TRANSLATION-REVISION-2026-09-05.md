# 翻译复核优化：2026-09-05

本轮将共享词元翻译路径的复核从整窗重写改为带原文证据的局部修订。它改善了修订约束，但尚未证明质量档优于速度档，也没有为新结果生成正式分数。

## 交付行为

- 模型只返回需要修改的固定 ID、该条原文连续引用、具体问题和修正后的完整译文。正确条目无需抄写；未提及条目保留原译文。
- 引用必须属于该 ID 的原文，未知/重复 ID、空问题、空译文及原有专名、数字等校验失败时整体回退。完全相同的译文不算修改，其多余引用不会阻挡其他有效修订。
- 提示词重点检查比较属性、动作角色、手段与结果、嵌套动作和词语的语境含义。未将开发集原句、答案或评分传入生产提示词。
- 保持每窗最多一次复核、均衡 12 秒/质量 25 秒复核超时、失败保留可用初稿及用户取消语义。速度档首轮提示词和流程未改。
- 策略版本为 `playback-policy-v4`，首轮流程版本为 `first-pass-v5`。此处是词元路径；不据此声明桌面固定 cue 路径已接入相同复核。

## 固定输入重跑

同一模型 `gemini-3.5-flash-lite`，相同 3 个视频的 9 个 development 片段，各运行一次；翻译请求没有访问评审参考。以下是完整性与流程统计，不是语义评分。

| 运行       | 完整片段 | 缺失计分词元 | 请求数 | 复核采用/回退 |
| ---------- | -------: | -----------: | -----: | ------------: |
| 旧质量基线 |      9/9 |            0 |     50 |          22/1 |
| 本轮质量   |      9/9 |            0 |     49 |          21/2 |
| 本轮均衡   |      9/9 |            0 |     29 |           2/0 |

本轮质量的两次复核回退为超时；完整结果仍由初稿提供。请求数变化也受到初译、分段和恢复差异影响，不能据此推断节省成本。部分请求没有 usage，未比较 token 费用。速度档沿用冻结基线，没有重新运行。

对已知问题逐条查看，本轮质量输出中：

- `interview-entities` 仍将 “more expensive” 表达为“更高阶”，价格属性依然错误。
- `food-frequency` 将语境中的 “normally” 表达为“常常”，不再是“正常”。
- `science-types` 完整表达了“通过提前制作病原体档案来识别攻击”。

均衡档该次输出中的价格和自卫含义正确，但 `science-types` 仍未明确表达学习“识别”的动作。以上仅是已知问题的定点核对，不能取代整套独立评分；新初译具有随机变化，不能把全部变化归功于复核。

## 隔离复核的诊断

将旧质量运行保存的原文范围和草稿原样交给新复核，仅调用复核阶段：三处已知问题中，价格属性和词语语境得到修正，识别动作遗漏仍未修复。这比重新翻译更直接地检验复核能力，但属于开发集诊断，没有统计显著性或独立盲评含义。

也试过先不看草稿、额外提取原文要点，再逐项对照的方案。它增加调用次数，仍会漏掉相同问题，因此没有进入交付代码。另一个精简英文审校提示的三次诊断出现两次超时和一次无效引用，也未采用。所有实验结果保留，没有只保留成功输出。
