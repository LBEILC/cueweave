# 三档翻译核心：首轮代理匿名评审

日期：2026-09-05。标准：`translation-quality-v1`，哈希 `199b5f5988d44508395aa0775420025041259486d3b1e85ece53b7356434e993`。这是对已保存输出的离线代理评审，不是人工金标准，不是新的翻译运行，也不是音画同步验收。

## 范围与方法

三位子代理使用相同模型配置，但各自从不继承优化对话的新上下文独立评审。每位查看三档各九段 development 输出，共 27 个候选片段；总计 81 次片段评审。输入来自三个视频，覆盖访谈、日常对话和科普。没有使用 holdout 或重新调用翻译模型。

每位评审收到单独随机映射的 P/Q/R 代号，片段呈现顺序也打乱；不提供档位、模型、耗时、恢复过程或之前的主观估分。原文、计分范围、冻结参考与评分标准可见。组织者在原始评审全部收齐后才汇总档位映射，不将某位评审的发现转告其他评审。

各评审对同一候选的成绩，先按同一视频内片段平均，再按视频等权平均。下表是按既有规则纠正一处误罚后的记录；没有将三位评审合成一个“官方分数”。小数来自公式，不代表判断具有小数级精度。

| 评审者 | 速度优先 |  均衡 | 质量优先 |
| ------ | -------: | ----: | -------: |
| 代理 1 |    92.78 | 87.92 |    90.00 |
| 代理 2 |    93.19 | 88.61 |    90.69 |
| 代理 3 |    94.31 | 89.72 |    92.78 |

三位在本批输出中均给出速度 > 质量 > 均衡的顺序。质量档没有显示出稳定优于速度档的收益；但只有三个视频、每档一次翻译输出，不能推断所有视频上的顺序，也不能把相近分差解释为统计显著。该结果不自动改变产品默认档位。

## 高总分没有消除实质错误

| 档位     | 三位评审各自记录的 major 数 | 各自标为需修复的片段数 /9 |
| -------- | --------------------------- | ------------------------- |
| 速度优先 | 2、2、1                     | 2、2、1                   |
| 均衡     | 2、2、1                     | 2、2、1                   |
| 质量优先 | 2、3、1                     | 2、3、1                   |

没有评审记录 critical，所有计分范围均有输出。以上只是这些评审的发现，不证明不存在其他严重错误；不能把 90 多分称为 90% 以上准确率或人工校译水平。

各评审一致识别的主要问题：

- **质量档**：将价格更高译成能力更强，丢失价格维度并改变含义。
- **均衡档**：将保护自身译成抵御自身，改变了免疫防御对象。
- **速度档**：把预先建立档案以识别攻击的关系，译成通过识别攻击来建立档案，手段与结果倒置。
- **三档共同**：教学语境中的 normally 被译为“正常”，没有保留频率含义；三位均认为有误，但对 minor/major 的判断不同。

因此，本轮提供的是较一致的候选排序和可定位问题，并不能据总分宣布某档质量达标。先前的 75–85 主观估分没有采用此标准和严格计分边界，不与本表直接比较。

## 规则复核与保留的分歧

代理 1 和代理 3 起初对 Astro→Astra 归一化扣了 minor 分。组织者核对发现，冻结参考明确允许有输入证据的归一化，同一输入又多次出现 Astra，因此请这两位各自重读既有规则，仅复核此项，未要求改分、未透露档位或其他评审结论。两位均认定原扣分未正确应用允许变体，撤销该项；仅 interview-entities 的相关问题、说明和必要等级改变。原始文件保留，另写 revised 与 addendum；复核后的六份报告再次通过校验。代理 2 原本接受这一变体。

原始评分如下，供审计复核影响：

| 评审者 | 速度优先 |  均衡 | 质量优先 |
| ------ | -------: | ----: | -------: |
| 代理 1 |    91.67 | 86.81 |    90.00 |
| 代理 2 |    93.19 | 88.61 |    90.69 |
| 代理 3 |    93.19 | 88.61 |    92.78 |

仍保留且未强行裁决的分歧包括：教学词误译属于轻微还是实质错误；同一价格属性错误是否还应降低完整性；科普中省略“识别攻击”属于次要还是重要信息缺失。对应五个档位/片段组合的证据和等级差保存在详细报告中。这说明代理评审也会误用规则，仍需要人工抽查和严重程度校准。

## 可追溯记录与后续用途

运行输入为 `.eval/benchmarks/three-modes-{speed,balanced,quality}-final`，原始质量基线使用 gemini-3.5-flash-lite / auto。输入、参考、评分标准和运行输出的哈希随每份评审记录并校验，不将旧判断套到新输出。

匿名材料、身份映射、原始评审、限定复核、15 份正式报告（9 份原始、6 份复核）和汇总，位于本地忽略目录 `.eval/reviews/blind-20260905/`。汇总入口为 `REPORT.md`，机器可读记录为 `aggregate.json`。原始字幕及评审正文不提交 Git。

评分工具验证了证据引用、范围、等级与严重程度约束；组织者核对了共同实质问题及允许变体分歧。没有修改算法、提示词、默认档位或评分公式。后续核心优化优先处理属性维度、反身关系和手段/结果关系，并按相同标准比较新的冻结候选；评分侧先校准严重程度和跨维度重复扣分边界，再扩大到未参与调试的视频。
