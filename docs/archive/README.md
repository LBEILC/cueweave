# 历史资料与恢复

[早期设计方向](design-initial.md)保存已停用的视觉方案。现行产品与设计规则分别由 [PRODUCT.md](../../PRODUCT.md) 和 [DESIGN.md](../../DESIGN.md) 维护。

## 本地归档

评测结果、模型请求记录、临时实验脚本和界面评审资料按归档日期保存在仓库根目录的 `.archive/YYYY-MM-DD/`。此目录被 Git 忽略；克隆仓库不会取得这些资料，需要备份时应另行复制归档目录。

每批归档包含 `history.zip` 和 `manifest.json`。清单记录包的 SHA-256、文件原路径、大小、SHA-256，以及留在工作目录的数据路径。包内保留相对于仓库根目录的路径，例如 `.eval/runs/...` 和 `.impeccable/review/...`。

仍被脚本或测试直接读取的基线保留在 `.eval`，设计 brief 引用的基准截图保留在 `.impeccable/review`。新增评测继续使用原有路径；[评测指南](../EVALUATION.md)说明运行与报告生成方式。

## 查找与恢复

1. 在各批次 `manifest.json` 的 `files` 中按 `path` 查找所需资料。
2. 使用 PowerShell 的 `Get-FileHash -Algorithm SHA256 -LiteralPath <归档包路径>`，核对结果与清单中的 `archiveSha256` 一致。
3. 将归档包解压到新的临时目录。包内报告携带字体和请求记录，查看时保留目录结构。
4. 需要回放实验时，将所需运行目录按清单中的原路径复制回仓库。若原路径已经存在，先比较内容，避免覆盖更新的结果。归档脚本按保存时的源码环境使用，历史文件中的绝对路径可能需要调整。

已归档资料保留其历史内容；其中的旧方案、路径和结论不替代现行文档。
